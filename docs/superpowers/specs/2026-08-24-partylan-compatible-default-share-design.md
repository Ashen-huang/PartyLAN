# PartyLAN 跨端兼容默认共享档位与网页窗口捕获回退设计

**日期：** 2026-08-24  
**状态：** 已获批准，待编写实施计划  
**范围：** Windows 客户端、广州节点网页端注入脚本

## 背景

当前客户端默认使用“原始画质/60 FPS”，网页端首次使用默认使用 `1280×720/30 FPS`。原始画质和高帧率会把窗口实际尺寸、浏览器捕获能力、显卡编码器能力以及上行带宽直接带入首次共享路径，兼容性最差。

最近 `xiusxiu` 网页共享者能够在 Edge 共享选择器中选中应用窗口，但确认后立即失败，随后改用全屏共享成功。服务端只能看到共享未建立，浏览器本地 `getDisplayMedia` 的具体异常不会上传。现有脚本还会向浏览器附加窗口音频、系统音频和画面约束，这些扩展约束在部分浏览器窗口捕获路径上可能导致立即拒绝。

## 目标

- 客户端与网页端统一以 `1280×720@30 FPS` 作为首次共享默认档位。
- 保留网页端和客户端已有的手动高画质档位与动态降档能力；默认值不等于锁定值。
- 网页端首选捕获约束失败时，对可恢复的浏览器参数/读取错误只自动重试一次基础约束，提升应用窗口共享成功率。
- 用户主动取消授权、没有找到共享源或页面状态无效时不重复弹出选择器。
- 记录首选约束失败类型和回退结果，便于后续按浏览器版本和共享面分析。
- 修复共享前画质弹窗确认后偶发“无事发生”的启动竞态。
- 不改变 Screego、P2P、SFU、TURN、Presence、语音隔离或客户端最小化窗口自动还原行为。

## 方案

### 默认档位

网页端的 `localStorage` 默认值改为 `resolution=1280x720`、`framerate=30`；已有用户保存的更高档位不被覆盖。客户端共享设置对话框的初始状态改为 `1280×720`、`30 FPS`；用户仍可选择“原始画质”、1080p、45/60 FPS。

默认档位是采集请求的初始上限。启动后的逐观看者自适应仍可降档和恢复，但不会在用户选择 720p/30 时凭空超过该采集上限。

### 网页端首选与回退捕获

网页端继续先按用户设置请求目标分辨率、帧率和音频模式。若 `getDisplayMedia` 在用户完成选择后以 `TypeError`、`OverconstrainedError` 或 `NotReadableError` 失败，则清理首个请求的轨道/共享租约，并允许一次新的选择器请求：

- `video: true`；
- 音频模式为 `off` 时使用 `audio: false`，其他模式使用 `audio: true`；
- 不发送 `systemAudio`、`windowAudio`、`selfBrowserSurface`、`surfaceSwitching` 和分辨率/帧率约束。

回退成功后仍经过现有音频安全过滤和 WebRTC 发送参数自适应。若浏览器没有提供符合所选音频模式的音轨，沿用现有“仅共享画面”提示。回退失败时只展示最终错误，并保留首个错误类型用于诊断日志；`NotAllowedError`、`AbortError`、`NotFoundError`、`InvalidStateError` 不触发回退。

### 客户端窗口共享

继续使用现有 `PrepareForShare` 流程：最小化窗口先还原，取得稳定窗口尺寸后再启动 WGC/NVENC。默认改为 720p/30 后，仍允许用户手动选择原始画质或高帧率；本设计不修改客户端原生编码器和窗口采集实现。

### 共享设置弹窗启动时序

当前确认按钮在同一事件栈中先启动原生 `getDisplayMedia`，再立即对可能已经重绘的 Screego “开始共享”按钮调用 `.click()`。系统选择器打开期间，后一个程序化点击可能被浏览器或页面事件队列丢弃，造成确认后没有任何共享状态变化。

确认按钮只允许一个进行中的启动操作。它仍在用户手势中创建首选捕获请求，但关闭设置弹窗后等待该请求完成，再重新查找当前仍连接的原始“开始共享”按钮并以旁路标记触发一次点击，让原始 Screego 流程消费已取得的同一条媒体 Promise。首选请求取消或失败时清理租约和轨道，并显示明确错误，不再触发第二次隐藏点击；页面重绘或重复确认不会产生第二个捕获请求。

## 验证

- 新增网页注入脚本测试，覆盖：默认设置、首选请求成功不重试、窗口捕获可恢复错误只重试一次、用户取消不重试、首选与回退轨道均清理、设置弹窗确认只消费一条捕获 Promise 并在 Promise 完成后触发当前开始按钮。
- 更新前端设置测试，断言客户端默认 `1280×720@30` 且保留原始画质和 60 FPS 选项。
- 运行服务器 Node/Python 测试、前端 Node 测试、前端生产构建和普通/`partylan_native_media` Go 全仓测试。
- 运行 `git diff --check`、脚本语法检查、资源副本摘要核对和敏感信息扫描。
- 在线灰度时分别测试 Edge 应用窗口、Edge 标签页、全屏共享，以及窗口音频可用/不可用路径；记录首选失败错误、回退结果、最终分辨率和帧率。

## 非目标

- 不强制所有用户迁移已保存的网页画质设置。
- 不把窗口共享自动转换为全屏共享。
- 不修改服务端媒体转发策略或动态画质阶梯。
- 不把浏览器不支持的窗口音频伪装成可用音频。
