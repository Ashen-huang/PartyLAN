# PartyLAN 网页端悬停工具层设计

**日期：** 2026-08-24  
**状态：** 已确认设计，待文档审阅  
**范围：** 仅网页端 `server/screego/deploy/inject.js` 与网页端测试；不修改 Wails 客户端

## 背景

网页端当前运行在 Screego 原生房间界面上，PartyLAN 通过 `inject.js` 增强成员 Presence、共享设置、画质控制和链路诊断。现有诊断面板信息完整且实测有用，应继续保留；成员列表和共享设置占用的视觉空间较大，也会与观看画面产生竞争。

本次目标是让成员列表和共享控制在网页观看区边缘按需出现，同时保持 Screego 原始观看区的宽高和媒体渲染比例不变。

## 目标与非目标

### 目标

- 在网页端新增左右边缘悬停工具层。
- 左侧显示紧凑的统一房间成员 Presence 列表。
- 右侧显示紧凑的共享状态、质量设置和共享入口。
- 保留现有 `gc-stats-overlay` 诊断面板的位置、展开逻辑和数据内容。
- 共享工具层不改变观看区的布局尺寸，不触发视频比例重算或布局跳动。
- 共享设置弹窗在确认捕获期间保持固定，避免因鼠标移开导致设置或捕获流程中断。
- 无 hover 的设备提供边缘手柄点击打开和明确关闭路径。

### 非目标

- 不修改 `frontend/src`、Wails 客户端 UI 或客户端媒体逻辑。
- 不修改 Screego 的 P2P/UDP、SFU、Presence、音频和自适应策略。
- 不让 hover 自动触发 `getDisplayMedia`、共享租约或任何媒体申请。
- 不改变网页观看区的原始比例、全屏行为和诊断数据来源。
- 不在非统一房间删除 Screego 原生成员提示。

## 方案

### 1. 固定悬停容器

注入一个 `gc-hover-tools` 根容器，使用 `position: fixed`，覆盖在网页视口边缘，不参与 Screego 主内容的文档流。根容器只在房间 URL 存在时显示。

左右各有一个约 14–18px 的悬停热点：

```text
┌─ 左热点 ─────────────────────────────── 右热点 ┐
│  成员抽屉       Screego 原始观看区       共享抽屉 │
│                    诊断面板保持原位              │
└────────────────────────────────────────────────┘
```

抽屉默认通过 `transform` 移出视口，仅保留热点；鼠标进入热点或抽屉、抽屉内元素获得焦点时展开。展开和收起只使用 `transform`/`opacity`，过渡时间控制在 150–300ms，避免布局重排。

### 2. 成员抽屉

成员抽屉宽度约 220–240px，复用现有 Presence 成员数据和 `renderWebPresenceMembers` 的标签规则：网页端/客户端、房主/成员、当前成员、共享中。

统一房间中，抽屉使用新增的稳定挂载点 `#gc-web-presence-roster`；现有 `#partylan-presence-roster` 仍保留在 Screego Tooltip 内，并由同一个渲染函数同步更新，避免破坏原生成员入口。原生 `data-partylan-legacy-roster` 继续隐藏。非统一房间不改变现有 Screego 成员提示，抽屉不接管旧链路。

成员条目保持单行截断、状态文字与共享状态同时可读；不依赖颜色单独表达在线或共享状态。

### 3. 共享抽屉与设置面板

共享抽屉宽度约 260–300px，显示：

- 当前共享阶段和共享者；
- 当前分辨率、帧率和质量偏好；
- 现有共享入口和停止入口；
- 统一房间的锁定/不可用原因；
- 音频模式和快速画质设置（沿用现有存储与策略）。

hover 只负责展示控制，不启动捕获。用户点击开始共享后，现有用户手势、一次性兼容回退和租约生命周期继续生效。

`gc-share-setup-modal` 改为紧凑的侧向设置面板，但仍由明确点击打开。捕获 Promise 未完成时面板保持打开；确认、取消、失败和页面重绘路径继续使用现有序号与清理逻辑。

### 4. 诊断面板

不移动、不折叠、不改写 `gc-stats-overlay` 的数据和展开交互。悬停工具层的层级低于诊断面板，不能遮挡诊断展开内容；如发生空间重叠，诊断面板优先显示。

### 5. 移动和无 hover 环境

使用 `matchMedia('(hover: hover) and (pointer: fine)')` 区分桌面 hover 和触摸设备。触摸设备显示可点击的边缘手柄，点击后固定抽屉，并显示关闭按钮；点击抽屉外部关闭。键盘用户通过焦点进入抽屉，按 `Escape` 关闭。

## 数据流与生命周期

```text
Presence/room state
      │
      ├─ renderWebPresenceMembers ──> Tooltip 挂载点 + 成员抽屉挂载点
      │
Share/quality state
      │
      └─ syncShareButtonAvailability ──> 共享抽屉状态

hover/focus/click ──> 仅改变 UI 可见性
明确点击开始 ──> 现有 capture/lease/SFU 生命周期
```

房间离开、URL 不再包含房间、页面卸载时销毁抽屉 DOM，清除悬停/固定状态；不额外创建 Presence 心跳、共享租约或媒体轨道。

## 可访问性与视觉约束

- 每个边缘手柄和关闭按钮提供 `aria-label` 与键盘焦点样式。
- 抽屉宽度、文字行高和控件高度保持在窄屏可用范围，移动端不产生横向滚动。
- 错误消息显示在对应共享控制附近，并保留明确的重试/取消路径。
- 使用网页端现有主题令牌，减少新增硬编码颜色；诊断面板保留现有深色高对比样式。
- 尊重 `prefers-reduced-motion`，关闭过渡动画但不改变展开逻辑。

## 测试与验收

增加或扩展网页端测试，覆盖：

1. 统一房间创建成员抽屉和共享抽屉，非统一房间不接管原生成员提示。
2. Presence 更新只更新成员条目，不重建观看区或媒体元素。
3. hover、focus、Escape 和触摸点击路径的可见性与清理行为。
4. 共享设置确认期间鼠标离开不会移除面板；取消、失败和重复确认仍只触发一次捕获。
5. `gc-stats-overlay` 始终存在且优先级高于工具层。
6. 工具层显示前后主观看容器的 `getBoundingClientRect()` 宽高一致。
7. `node --check server/screego/deploy/inject.js`、网页端 Node 测试和生产构建通过。

完成后通过桌面浏览器和触摸模拟分别验证：成员悬停、共享设置、诊断展开、全屏、窄窗口和房间退出。

## 风险与回滚

主要风险是 Screego/MUI DOM 在版本更新后改变成员 Tooltip 或共享按钮的挂载位置。实现应通过稳定的 `data-*` 标记和现有 PartyLAN 注入 ID 定位，不依赖深层次临时 class。若注入失败，原生 Screego 观看和共享链路应保持可用；回滚只需恢复上一版 `inject.js` 和缓存版本号。
