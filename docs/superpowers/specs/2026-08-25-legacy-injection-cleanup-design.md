# PartyLAN 网页端旧注入层清理设计

**日期：** 2026-08-25  
**状态：** 已确认  
**范围：** 仅网页端，不修改桌面客户端和媒体协议

## 目标

移除旧版网页 UI 注入层，避免它继续监听、翻译、重排或覆盖 Screego 原生 React 页面。网页房间由原生 React UI 负责成员、共享、全屏、设置和退出操作；`inject.js` 仅保留媒体与连接运行时兼容能力。

## 保留边界

以下能力必须继续工作：

- `getDisplayMedia` 采集包装、共享状态标记和共享轨道清理。
- WebSocket/Fetch 的 SFU、Presence 和连接兼容钩子。
- WebRTC 统计、恢复、动态画质及既有诊断遥测。
- `partylanMode`、共享租约和房间刷新恢复所依赖的运行时状态。
- Nginx 仍通过现有 `/inject.js` 入口加载脚本，避免扩大部署变更面。

## 移除边界

删除或停用以下旧 UI 行为及其静态资源：

- 旧悬停侧栏、成员抽屉、全屏工具条和退出/设置按钮注入。
- 全局 MutationObserver、DOM 文本翻译和旧 Snackbar/对话框增强。
- 旧共享按钮点击转发、快捷键转发、共享设置弹窗和质量下拉注入。
- 登录/注册入口、房间历史下拉、Logo 替换及 Screego 设置隐藏。
- 全局主题 CSS、旧移动端工具栏样式和 UI 定时刷新器。

清理后，脚本不得创建第二套工具栏，不得改写 `#partylan-presence-roster` 或原生共享按钮，也不得依赖页面 DOM 结构来驱动共享。

## 实现策略

采用原地瘦身方案：保留 `inject.js` 文件名和 Nginx 资源入口，按函数边界删除 UI 注入代码，保留媒体/协议钩子。初始化流程不再启动 DOM 观察器，也不再调用主题、翻译、旧弹窗和侧栏渲染函数。

## 验证

- 静态检查：注入脚本不得包含旧 UI 根节点、全局观察器启动和旧共享点击拦截调用。
- 行为回归：网页共享、取消共享、刷新重连、Presence、SFU-only 和 WebRTC 恢复测试全部通过。
- 原生 UI 回归：原生 React 单测和生产构建继续通过。
- 部署检查：Nginx 仍引用当前缓存版本，资源可正常加载。

## 回滚

回滚 `inject.js` 和对应 Nginx 缓存版本即可恢复旧注入层；不需要回滚原生 React UI 或媒体服务。
