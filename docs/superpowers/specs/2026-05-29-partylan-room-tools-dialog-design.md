# PartyLAN 房间工具弹窗与诊断叠层设计

## 1. 背景

当前房间界面里有三类信息长期占用主界面空间：

- 共享设置直接展开在房间控制面板中。
- 音频控制作为 `AudioPanel` 常驻在视频舞台下方。
- 房间诊断作为完整面板常驻在成员侧栏中。

这些信息都重要，但不是房间内每一秒都需要操作。新的目标是把低频设置收进弹窗，让房间界面更专注于成员列表、共享舞台和少量关键按钮。

本轮也会把 `internal/voice` 的现有语音通道入口接到前端，但只作为界面与状态入口接线，不补完整真实麦克风采集、扬声器播放或多人语音质量闭环。

## 2. 目标

- 点击 `开始共享` 后先打开弹窗，在弹窗中设置画面参数、共享音频来源，然后确认开始共享。
- 房间用户列表下方增加 `语音聊天` 按钮，点击后打开同一个房间工具弹窗，并默认切到语音页。
- 语音聊天页接入现有 `internal/voice` 的开始、停止、静音、音量与状态事件入口，但标注为实验性能力。
- 移除房间主界面中常驻的 `AudioPanel`，把相关控件收纳进弹窗。
- 房间诊断从侧栏面板改成视频窗口内的半透明性能列表叠层。
- 设置弹窗中增加 `显示房间诊断叠层` 开关，用于显示或隐藏视频内诊断列表。
- 默认保持诊断叠层显示，避免丢失当前已有诊断可见性。

## 3. 非目标

- 不实现真正可用的 Windows 麦克风输入与扬声器输出。
- 不重写 `internal/voice` 的网络传输模型。
- 不做多人语音混音、回声消除、降噪或设备选择。
- 不把当前单 peer `VoiceChannel` 扩展成完整多人语音架构。
- 不改动视频共享编码、捕获、解码链路。
- 不新增路由或全局状态库。

## 4. 推荐方案

采用统一的 `RoomToolsDialog`。

弹窗包含三个页签：

- `屏幕共享`
- `共享音频`
- `语音聊天`

打开入口：

- 点击房间控制区的 `开始共享`：打开弹窗并默认进入 `屏幕共享` 页。
- 点击成员列表下方的 `语音聊天`：打开同一弹窗并默认进入 `语音聊天` 页。

这样能避免多个弹窗分散，也能把房间内所有低频控制集中到一个地方。

## 5. 前端设计

### 5.1 App 状态

`frontend/src/App.tsx` 增加轻量 UI 状态：

- `roomToolsOpen`
- `roomToolsInitialTab`
- `diagnosticsOverlayVisible`
- `voiceStatus`

`diagnosticsOverlayVisible` 默认 `true`，并通过 `localStorage` 保存用户选择。该偏好不需要进入 Go 配置文件。

`voiceStatus` 用于展示前端语音状态，初始为 `idle`。可选状态：

- `idle`
- `starting`
- `active`
- `muted`
- `error`

### 5.2 RoomControls

`RoomControls` 不再直接渲染分辨率与帧率选择。

房间内未共享时：

- `开始共享` 按钮只负责打开房间工具弹窗。
- 真正调用 `StartSharing` 发生在弹窗的确认按钮中。

共享中：

- 保留 `停止共享`。
- 保留 `离开房间`。

### 5.3 RoomToolsDialog

新增组件：

- `frontend/src/components/RoomToolsDialog.tsx`
- `frontend/src/components/RoomToolsDialog.css`

组件职责：

- 管理共享画面设置：分辨率、帧率。
- 管理共享音频设置：复用当前 `AudioPanel` 中的应用音频来源列表。
- 管理语音聊天设置：开始/停止语音、静音、输出音量、实验性说明。

弹窗只负责 UI 与回调，不直接持有业务状态源。业务状态继续由 `App.tsx` 统一管理。

### 5.4 AudioPanel 收纳

现有 `AudioPanel` 可以有两种实现方式：

- 将其内容拆出为可嵌入 `RoomToolsDialog` 的子视图。
- 或保留组件名，但改成只在弹窗里渲染。

推荐保留组件并增加紧凑弹窗样式，减少改动。

房间主界面不再渲染常驻 `AudioPanel`。

### 5.5 语音聊天按钮

`MemberList` 下方新增一个轻量操作区，渲染 `语音聊天` 按钮。

按钮显示：

- 未开启：`语音聊天`
- 启动中：`连接中`
- 已开启：`语音已开启`
- 静音：`已静音`
- 错误：`语音异常`

点击按钮打开 `RoomToolsDialog` 的语音页，而不是直接切换状态。这样可以避免用户误触开启实验性语音。

### 5.6 诊断叠层

`DiagnosticsPanel` 增加 `variant="overlay"` 或等价 prop。

overlay 形态要求：

- 渲染在 `ScreenPreview` 的视频窗口内。
- 半透明深色底，像性能检测软件的状态列表。
- 小字号、单列或双列，优先显示关键项。
- 不阻挡视频中心区域，默认放在左上角或右上角。
- 不使用完整卡片边框和大标题。

`ScreenPreview` 接收 `diagnosticsOverlay` 或相关 props，由 `App.tsx` 决定是否显示。

设置弹窗中增加一个开关：

- `显示房间诊断叠层`

开关只影响房间视频窗口内的叠层，不影响设置弹窗里已有的诊断详情。

## 6. 后端设计

### 6.1 App 字段

`app.go` 增加最小语音状态字段：

- `voiceChannel voice.VoiceChannel`
- `voiceActive bool`
- `voiceMuted bool`
- `voiceVolume float32`

这些字段只用于接线现有 `internal/voice`，不代表真实语音设备已经完善。

当前 `VoiceChannel` 是单 peer 通道。本轮只做最小接线：

- 有远端成员时，优先选择第一个远端 peer 作为 voice peer。
- 没有远端成员时，允许进入本地实验状态，用于验证 UI 生命周期。
- 不为每个成员创建独立 voice channel。
- 不保证多人语音收发成立。

### 6.2 Wails 方法

新增方法：

- `StartVoiceChat() error`
- `StopVoiceChat() error`
- `SetVoiceMuted(muted bool)`
- `SetVoiceVolume(volume int)`
- `GetVoiceState() map[string]interface{}`

行为约束：

- 不在房间内时，`StartVoiceChat` 返回错误。
- 没有远端成员时，可以进入本地 active 状态，但 UI 需要显示实验性提示。
- 如果 `internal/voice` 启动失败，前端进入 `error` 状态并显示错误。
- 停止语音、离开房间、房间失效时清理语音状态。

### 6.3 事件

复用已有事件：

- `peer:voice-state`

前端监听该事件，并更新成员说话状态或语音弹窗状态。

本轮不要求语音状态准确反映真实声卡输入，因为底层仍是现有 `internal/voice` 能力。

## 7. 数据流

开始共享：

1. 用户点击 `开始共享`。
2. `App.tsx` 打开 `RoomToolsDialog`，默认页为 `屏幕共享`。
3. 用户选择分辨率、帧率、共享音频来源。
4. 用户点击确认。
5. `App.tsx` 调用现有 `StartSharing(display,width,height,fps)`。
6. 弹窗关闭，舞台进入已有共享状态。

打开语音：

1. 用户点击成员列表下方 `语音聊天`。
2. `App.tsx` 打开 `RoomToolsDialog`，默认页为 `语音聊天`。
3. 用户点击开始语音。
4. 前端调用 `StartVoiceChat()`。
5. 后端尝试启动现有 `internal/voice`。
6. 前端根据结果显示 `active` 或 `error`。

诊断叠层：

1. `App.tsx` 维护 `diagnosticsOverlayVisible`。
2. `SettingsPanel` 修改该状态并写入 `localStorage`。
3. `ScreenPreview` 根据状态渲染或隐藏 overlay 版 `DiagnosticsPanel`。

## 8. 错误处理

- 共享确认失败时，保留弹窗并显示现有错误信息。
- 共享音频来源设置失败时，沿用当前错误提示。
- 语音启动失败时，不关闭弹窗，显示错误并将按钮恢复为可重试。
- 离开房间时强制关闭房间工具弹窗，并清理语音状态。
- 诊断叠层开关读取 `localStorage` 失败时，回退为默认显示。

## 9. 测试与验证

静态验证：

- `cd frontend && npm run build`
- `go test ./...`

手工验证：

1. 创建或加入房间。
2. 确认房间侧栏中不再显示常驻诊断面板。
3. 确认视频窗口内显示半透明诊断叠层。
4. 在设置中关闭诊断叠层，确认视频窗口内隐藏。
5. 点击 `开始共享`，确认先打开房间工具弹窗。
6. 在弹窗中设置分辨率和帧率后开始共享。
7. 确认房间主界面不再常驻显示 `AudioPanel`。
8. 点击成员列表下方 `语音聊天`，确认打开同一弹窗并进入语音页。
9. 点击开始/停止语音，确认 UI 状态变化；不要求真实可听可说。

## 10. 风险

- `internal/voice` 当前使用 mock capturer，接收端也没有真实播放输出，所以用户可能误以为语音已经完整可用。UI 必须明确显示实验性说明。
- 诊断叠层如果太大可能挡住共享画面，需要限制宽度、高度和透明度。
- 把音频面板收进弹窗后，共享音频选择的可见性降低；通过 `开始共享` 弹窗中的 `共享音频` 页解决。

## 11. 验收标准

- 房间界面更简洁：共享设置、共享音频、语音控制不再常驻占用主区域。
- 点击 `开始共享` 后出现弹窗，并能在弹窗内设置画面和音频后开始共享。
- 用户列表下方有语音聊天按钮，点击打开弹窗语音页。
- 语音页接入现有 voice 状态入口，但不承诺真实语音通话完成。
- 房间诊断显示为视频窗口内半透明性能列表。
- 设置中可以显示或隐藏房间诊断叠层。
- 前端构建通过，Go 测试通过或明确记录失败原因。
