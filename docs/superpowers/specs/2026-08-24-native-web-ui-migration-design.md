# PartyLAN 原生网页 UI 改造设计

## 目标与范围

本阶段只改造网页端 Screego 原生 React UI，不修改桌面客户端，不改变现有 SFU/UDP、P2P、Presence、动态画质和语音协议。网页端继续使用锁定的 Screego revision `f946cee83b61d9f47c2f1c2238fb31f4042b628a` 作为基线。

## 架构边界

直接修改原生 UI：

- `ui/src/Room.tsx` 负责右侧工具栏、成员面板、共享面板和全屏入口。
- `ui/src/useRoom.ts` 继续负责房间连接、媒体采集、共享启动/停止和现有 SFU/P2P 策略。
- 不修改桌面客户端，不改变 SFU/UDP、P2P、Presence、动态画质和语音协议。
- `inject.js` 暂时保留，但职责收缩为诊断、遥测、SFU 控制面兼容和旧版本回退辅助。
- 注入层不再创建主工具栏，也不再模拟点击原生共享按钮。
- 原生 UI 提供稳定的 `id`/`data-*` 锚点，供诊断脚本读取状态。

共享按钮的状态直接来自 React 房间状态，避免依赖 DOM/SVG 查找导致入口失效。

## 交互与布局

- 页面主体保持现有视频观看区域比例，工具栏不再固定占用底部中央位置。
- 右侧显示窄的图标触发条，鼠标悬停或键盘聚焦后展开。
- 侧栏统一放置共享、成员、全屏、设置、退出五项操作。
- 共享设置直接在侧栏中展开，包含分辨率、帧率、优先模式和音频源。
- 正在共享时，共享入口变为停止共享，并显示当前共享状态。
- 成员面板直接使用原生 `state.users`，同时保留 PartyLAN Presence 成员信息。
- 诊断面板保留为独立入口，不与操作面板嵌套成卡片。
- 移动端使用边缘抽屉，避免遮挡视频和共享画面。
- 旧底部工具栏在原生 React 渲染层移除，不依靠 CSS 覆盖或点击转发。

## 状态、错误与兼容

- 共享按钮直接调用 `useRoom` 的 `share()` / `stopShare()`。
- 共享状态以 `state.hostStream` 和房间状态为准，侧栏、成员列表和诊断面板使用同一来源。
- 取消系统选择器后恢复到可再次点击的 idle 状态，不留下“正在共享”的假状态。
- 捕获失败、编码器不支持、音频源失败等错误通过原生 Snackbar 显示，同时写入现有诊断遥测。
- 媒体轨道意外结束时自动清理共享状态和租约。
- SFU-only 房间继续由现有 `partylanMode` 控制；原生 UI 不直接决定媒体模式。
- 旧浏览器或原生资源加载失败时，保留注入层回退开关，能够恢复当前网页入口。
- 迁移期间保留旧版镜像和静态资源，支持只回滚网页 UI，不重启屏幕或语音 SFU。

## 构建、灰度与验证

实施与发布分为四个阶段：

1. 原生代码改造：新增侧栏组件和稳定锚点，移除原生底部工具栏渲染；不修改媒体协议。
2. 本地验证：运行 Screego UI 单元测试、PartyLAN 补丁测试、TypeScript 构建和 Go 回归测试。
3. 不可变镜像灰度：使用新镜像标签部署到广州节点，只让 `test` 房间加载原生 UI；保留当前版本作为回滚目标。
4. 真实场景验证：覆盖网页创建/加入房间、客户端加入网页房间、网页与客户端分别共享、窗口/全屏捕获、单观众/多观众、局域网/公网、音频、刷新重连、退出清理和移动端布局。

灰度期间重点观察：

- 页面进入房间是否仍会卡住；
- 右侧共享入口是否始终可用；
- 底部旧工具栏是否完全消失；
- 共享取消或失败后是否可立即重试；
- Presence 成员列表是否与客户端一致；
- 现有 SFU/UDP 与 P2P 链路质量是否没有回归。
