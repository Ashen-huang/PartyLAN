# Screego 网页窗口音频回归修复设计

## 1. 背景与结论

同一台 Windows 设备此前可以正常共享所选窗口的音频，当前故障不是设备或浏览器版本
变化导致。提交 `3a1900d` 在加强网页共享音频隔离时，将 `app` 模式从
`windowAudio: 'window'` 改为 `windowAudio: 'exclude'`，并在捕获后只允许
`displaySurface === 'browser'` 的音轨。所选来源为普通窗口时，即使浏览器返回了对应
窗口音轨，策略也会主动停止并移除该音轨。

广州生产节点当前使用同一策略：`app` 模式明确排除窗口音频，窗口流也不在允许列表
中。因此本设计采用已批准的受控恢复方案：重新请求浏览器提供所选窗口音频，只在
浏览器确认共享来源为标签页或窗口时保留音轨，不恢复任何系统音频后备路径。

## 2. 范围

### 2.1 目标

- 网页选择普通窗口共享时，同时共享该窗口由浏览器返回的音频。
- 标签页音频保持可用。
- “全屏系统音频”和“不共享音频”模式保持现有语义。
- 房间语音、系统音频和所选窗口音频继续隔离。
- 浏览器没有返回音轨时安全降级为纯画面，并给出非阻塞状态提示。
- 房间状态上报反映实际生效的网页音频模式。
- 本地验证通过后部署到广州节点，并保留可立即恢复的静态资源备份。

### 2.2 非目标

- 不使用系统混音模拟窗口音频。
- 不修改 PartyLAN 原生客户端的进程树音频捕获逻辑。
- 不修改独立房间语音的设备、编码、SFU 或生命周期。
- 不修改当前已无法复现的共享权限释放逻辑。
- 不新增浏览器、操作系统或窗口类型白名单。
- 不保证浏览器本身不提供窗口音频时仍能生成窗口音轨。

## 3. 不可破坏的隔离约束

1. `app` 模式必须同时设置 `systemAudio: 'exclude'` 和
   `windowAudio: 'window'`。
2. `app` 模式只允许 `displaySurface` 为 `browser` 或 `window` 的捕获音轨。
3. `system` 模式只允许 `displaySurface === 'monitor'` 的捕获音轨。
4. `off` 模式、未知来源和模式不匹配的来源必须停止并移除全部捕获音轨。
5. 不得使用 `windowAudio: 'system'`、系统 loopback、麦克风或房间语音作为窗口音频
   后备。
6. 是否保留音轨由浏览器返回的共享来源和实际音轨共同决定，不能只相信用户界面中
   预先选择的模式。
7. 音轨策略必须在流进入原生 Screego 发布和自定义 SFU 发布之前执行。

## 4. 方案比较

### 4.1 采用方案：受控恢复窗口音频

恢复 `windowAudio: 'window'`，并把 `window` 加入 `app` 模式允许来源。该方案恢复已被
证明可用的浏览器能力，同时保留捕获后校验和强制删轨边界，改动集中且可回滚。

### 4.2 不采用：整体回滚到 `3a1900d` 之前

旧实现的 `system` 模式使用 `windowAudio: 'system'`，且没有捕获后来源校验。整体回滚
虽然也能恢复窗口音频，但可能把系统声音带入窗口共享，违反隔离要求。

### 4.3 不采用：新增独立“窗口音频”模式

浏览器共享选择器已经区分标签页和窗口。再新增模式需要扩展设置界面、持久化和服务端
状态枚举，却不能提高浏览器实际捕获能力，属于不必要的协议扩张。

## 5. 音频策略

| 请求模式 | `systemAudio` | `windowAudio` | 允许来源 | 有音轨时的有效模式 |
| --- | --- | --- | --- | --- |
| `app` | `exclude` | `window` | `browser`, `window` | `app` |
| `system` | `include` | `exclude` | `monitor` | `system` |
| `off` | 不请求音频 | 不设置 | 无 | `off` |

`app` 同时表示标签页和所选窗口音频。后端控制面已经接受 `app`，因此不新增 `tab` 或
`window` 状态值。当前代码在标签页成功时上报 `tab`，该值不在后端允许集合中，最终会
被归一化为 `off`；本次将其一并修正为 `app`。

## 6. 数据流

1. 用户在共享设置中选择“窗口/标签页音频”。
2. `buildCapturePreferences('app')` 生成排除系统音频、请求所选窗口音频的显示捕获偏好。
3. `inject.js` 将偏好与 Screego 原始 `getDisplayMedia` 约束合并。
4. 浏览器展示原生共享选择器，用户选择标签页或普通窗口。
5. 捕获完成后，`sanitizeCapturedStream()` 读取视频轨的 `displaySurface`。
6. 来源为 `browser` 或 `window` 且存在音轨时，原流和音轨保持不变。
7. 来源不匹配时，所有音轨立即停止并从流中移除；必要时构造仅含视频轨的新流。
8. 处理后的流才可赋给 `activeDisplayStream`，并进入 Screego 或自定义 SFU 发布路径。
9. 租约心跳和房间状态使用实际有效模式 `app`、`system` 或 `off`。

## 7. 状态与异常处理

- 允许来源但浏览器没有返回音轨：保留视频流，实际模式为 `off`，提示“未获取到所选
  来源音频，本次仅共享画面”。
- 来源不符合当前模式：删除音轨，实际模式为 `off`，提示音频因来源不匹配而关闭。
- 音频模式为 `off` 却意外返回音轨：静默删除，不显示安全提示。
- `displaySurface` 缺失或未知：按不可信来源处理，删除音轨。
- 音轨停止或共享结束：沿用现有流清理，实际模式恢复为 `off`。
- 策略处理异常不得回退为未校验的原始含音频流；共享应失败或保持纯视频。

状态提示只说明本次捕获结果，不指导用户绕过浏览器安全选择器，也不自动改用其他音频
来源。

## 8. 代码边界

主要修改：

- `server/web_share_audio_policy.js`
- `server/screego/deploy/web-share-audio.js`
- `server/screego/deploy/inject.js`
- `server/screego/deploy/nginx-screego.conf`
- `server/test_web_share_audio_policy.mjs`
- `server/test_web_share_audio_integration.mjs`

两个音频策略文件是源文件与部署副本，提交前必须逐字节一致。Nginx 只调整静态脚本
缓存版本，确保浏览器不会继续使用旧策略。`frontend/src/media/gamecastHost.ts` 属于原生
客户端的 WebView 兼容路径，仍保持纯视频，不纳入本次网页修复。

## 9. 测试设计

### 9.1 策略单元测试

- `app` 偏好必须为 `systemAudio: 'exclude'`、`windowAudio: 'window'`。
- `app + browser + audio` 保留音轨并返回有效模式 `app`。
- `app + window + audio` 保留音轨并返回有效模式 `app`。
- `app + monitor` 和 `app + unknown` 删除音轨。
- `system + monitor + audio` 保留音轨并返回 `system`。
- `system + browser/window/unknown` 删除音轨。
- `off` 删除任何意外音轨且不提示。
- 允许来源没有音轨时保持视频、返回 `off` 并要求提示。
- 被删除的音轨必须调用 `stop()`，返回流不得再含音轨。

### 9.2 集成与静态约束

- 策略脚本继续早于 `inject.js` 加载。
- `inject.js` 只从策略对象取得 `windowAudio`，不内联回退值。
- 捕获流必须在设为活动流和发布之前经过净化。
- 标签和说明恢复为“窗口/标签页音频”，不再宣称普通窗口必然静音。
- 房间状态和租约心跳上报实际有效模式。
- Nginx 静态资源版本递增。
- 源策略与部署策略 SHA-256 一致。

### 9.3 本地自动验证

- 运行网页音频策略和集成 Node 测试。
- 运行全部 `server/*.mjs` Node 测试，检查 WebRTC 生命周期、恢复和自适应逻辑无回归。
- 运行相关 Python 控制面测试，确认 `app` 状态仍被接受。
- 检查工作区差异只包含本设计范围内文件。

### 9.4 Windows 真机验收

在此前可正常工作的同一台 Windows 设备和 Edge 环境中验证：

1. 共享带声音的普通应用窗口，接收端能听到该窗口音频。
2. 同时播放另一个未共享应用的声音，接收端不能听到该声音。
3. 房间语音播放期间共享普通窗口，接收端共享音轨不能包含房间语音。
4. 共享浏览器标签页时标签页音频仍正常。
5. 选择“不共享音频”时接收端没有共享音轨。
6. 选择全屏系统音频时维持现有整屏行为。
7. 未勾选浏览器提供的音频选项时，共享继续成功但仅有画面，并出现状态提示。

自动测试不能代替该真机验收。

## 10. 广州部署与回滚

部署前备份广州节点的：

- `/var/www/screego/web-share-audio.js`
- `/var/www/screego/inject.js`
- `/root/screego/frontend/inject.js`
- `/etc/nginx/sites-available/screego`

上传时先写入同目录临时文件，校验 SHA-256 后原子替换。`inject.js` 的维护副本和服务副本
必须一致。运行 `nginx -t` 成功后只重载 Nginx，不重启 Screego、Registration Control、
屏幕 SFU 或语音 SFU。部署后通过 HTTPS 拉取静态资源确认新缓存版本和内容，再执行同一
房间的窗口音频真机验收。

若出现系统声音泄漏、标签页音频回归、共享失败或静态资源加载错误，恢复上述备份、
再次运行 `nginx -t` 并重载 Nginx。回滚不修改用户、房间、证书、容器或持久化数据。

## 11. 完成标准

- 普通窗口共享可以传输浏览器返回的对应窗口音频。
- 其他应用声音和房间语音不会进入窗口共享音轨。
- 标签页、全屏系统音频和无音频三种现有行为不回归。
- 不支持或未提供窗口音频时安全降级为纯视频。
- 控制面上报 `app`、`system` 或 `off`，不再产生无效的 `tab` 状态。
- 自动测试、本地差异审计、线上哈希检查和 Windows 真机验收分别有结果记录。
- 广州节点部署后无需刷新等待旧缓存，且具备已验证的静态资源回滚路径。
