# PartyLAN 设计规范

> 融合虚拟局域网、高性能屏幕共享、内嵌语音和独立音频流控制的 Windows 桌面应用

## 1. 概述

### 1.1 目标

为 5-10 人的固定团队打造一个开箱即用的 Windows 桌面应用，核心能力：

- **虚拟局域网**：基于 Tailscale 的 P2P 加密组网
- **高性能屏幕共享**：GPU 硬件加速捕获与编码，低延迟高画质
- **内嵌语音聊天**：独立于屏幕流的超低延迟语音通道
- **独立音频流控制**：应用级音频分离，彻底解决回声问题

### 1.2 技术决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 主语言 | Go (CGO) | 与 Tailscale 生态一致，并发和网络编程能力强 |
| UI 框架 | Wails + React + TypeScript | 开发效率高，界面灵活美观 |
| 虚拟局域网 | tsnet (Tailscale Go 库) | 自动 NAT 穿透，内置 DERP 中继，零额外部署 |
| 信令服务 | Tailscale 网络发现 | 零额外成本，利用已有虚拟网络 |
| 视频编码 | 自动选择 (H.265 优先, H.264 回退) | 兼容性与画质平衡 |
| 音频分离 | 虚拟音频设备驱动 | 最稳定的应用级音频隔离方案 |
| 远程输入 | 纯观看模式（可扩展） | MVP 简化，预留扩展接口 |

### 1.3 架构选型

采用 **单体 Go + CGO 桥接** 架构：

- 所有 C/C++ 代码通过 CGO 编译进单一 Go 二进制
- 模块间通过 Go channel 通信
- 部署简单（单文件），迭代速度快

## 3. 网络层设计

### 3.1 tsnet 集成架构

```
┌─────────────────────────────────────────────┐
│                 PartyLAN 应用                 │
│  ┌─────────┐  ┌──────────┐  ┌────────────┐ │
│  │ 房间管理 │  │ 视频流   │  │ 语音通道   │ │
│  └────┬─────┘  └────┬─────┘  └─────┬──────┘ │
│       │              │              │         │
│  ┌────┴──────────────┴──────────────┴──────┐ │
│  │          tsnet 虚拟网络栈               │ │
│  │  - 自动生成 WireGuard 密钥对           │ │
│  │  - NAT 穿透 (STUN/ICE)                 │ │
│  │  - DERP 中继回退                        │ │
│  │  - 虚拟 IP 分配 (100.x.x.x)            │ │
│  └────────────────┬───────────────────────┘ │
│                   │                          │
└───────────────────┼──────────────────────────┘
                    │ 加密隧道
         ┌──────────┴──────────┐
         │  Tailscale 控制平面  │
         │  (节点注册/密钥分发) │
         └─────────────────────┘
```

### 3.2 节点身份与认证

- 每个客户端启动时通过 `tsnet` 注册到团队的 Tailscale 网络
- 使用预共享密钥（auth key）认证，auth key 由团队管理员在 Tailscale 控制台生成
- 新成员通过 `RoomJoin` 请求加入房间后，房间创建者发送 `AuthKeyDistribute` 消息将 auth key 安全传递
- tsnet 自动生成 WireGuard 密钥对，管理加密隧道生命周期
- 首次加入后，节点身份持久化到本地配置文件，后续启动自动重连

### 3.3 连接建立

- tsnet 内置 ICE/STUN 穿透，优先 P2P 直连
- 失败时自动回退到 DERP 中继
- 自建 DERP 中继：部署在国内云服务器，确保低延迟
  - DERP 中继是一个简单的 HTTP/2 服务器，负责在 P2P 直连失败时转发加密流量
  - 部署方式：单台国内云服务器（2核4G即可），开放 443 端口
  - 配置：在 tsnet 启动时通过 `SetDERPMap` 注入自建 DERP 节点地址

### 3.4 数据传输

- 视频流和语音流均通过 tsnet 的加密隧道传输
- 无需额外加密层
- 端口分配：视频 base+1, 语音 base+2, 信令 base+3

## 4. 视频捕获与编码

### 4.1 DXGI 屏幕捕获流程

```
Windows桌面 (GPU合成)
    │
    ▼
DXGI Desktop Duplication API
    │
    ▼
GPU 纹理 (ID3D11Texture)
    │
    ├──────────────────────┐
    ▼                      ▼
GPU 硬件编码              CPU 回读 (备选)
NVENC/AMF/QSV            软件编码 x264
    │                      │
    ▼                      ▼
H.264/H.265 NAL 单元
    │
    ▼
tsnet 加密隧道 → 接收端解码渲染
```

### 4.2 编码器自动检测

1. 启动时检测 GPU 厂商和驱动版本
2. 优先级：NVENC (NVIDIA) > AMF (AMD) > QuickSync (Intel) > 软件编码
3. H.265 优先，不支持时回退 H.264
4. `encoder.go` 接口统一抽象，底层实现通过 CGO 调用各厂商 SDK

### 4.3 画质预设

| 模式 | 分辨率 | 帧率 | 码率 | 适用场景 |
|------|--------|------|------|----------|
| 流畅 | 720p | 30fps | 2-4 Mbps | 网络带宽有限 |
| 均衡 | 1080p | 30fps | 5-8 Mbps | 日常使用 |
| 高画质 | 1080p | 60fps | 10-15 Mbps | 游戏展示 |
| 原画 | 原始 | 60fps | 20+ Mbps | 设计/文字内容 |

### 5.1 音频架构总览

```
分享端 (Host)                              观看端 (Viewer)
┌─────────────────────────┐               ┌─────────────────────────┐
│  ┌─────────┐ ┌────────┐ │               │ ┌──────────┐            │

│  ┌────┴───────────┴────┐ │   tsnet隧道   │ ┌────┴──────────┐      │
│  │ 虚拟音频设备驱动    │ │───────────────│▶│ 音轨A: 应用音频│      │
│  │ (应用级音频分离)    │ │   轨道A       │ └───────┬────────┘      │

│      ┌──────┴──────┐     │               │    ┌────┴────┐          │

│  └────┬─────┘            │               │ └───────┬────────┘      │
│  ┌────┴─────┐           │               │    ┌────┴────┐          │
│  │ AEC处理  │           │               │    │ AEC回声 │          │
│  └────┬─────┘           │               │    │ 消除    │          │
│  ┌────┴─────┐           │               │    └────┴────┘          │
│  │Opus编码B │            │               │                         │
│  └────┬─────┘           │               │                         │
│       └─────────────────│───────────────│▶ 语音聊天独立播放       │
│                         │   轨道B       │                         │
└─────────────────────────┘               └─────────────────────────┘
```

### 5.2 虚拟音频设备驱动工作原理

1. **安装阶段**：安装程序部署虚拟音频设备驱动（基于 AVStream/WMF 框架）
2. **路由阶段**：将指定应用的音频输出路由到虚拟设备，而非物理扬声器
3. **捕获阶段**：从虚拟设备的环回接口读取该应用的纯净音频数据
4. **隔离效果**：
   - 游戏音频 → 虚拟设备 → Opus编码 → 发送给观看端
   - 微信音频 → 物理扬声器 → 本地播放（不共享）
   - 麦克风 → AEC处理 → Opus编码 → 独立语音轨道

### 5.3 回声消除策略

- **分享端**：AEC 参考信号来自虚拟设备（排除共享音频），确保麦克风不拾取共享的声音
- **观看端**：语音聊天音频直接输出到耳机，不经过共享音频轨道
- **结果**：彻底杜绝回声

### 5.4 驱动降级方案

虚拟音频设备驱动需要管理员权限安装，某些系统上可能失败。降级策略：

1. **检测阶段**：启动时检测虚拟音频设备驱动是否已安装且正常工作
2. **降级模式**：驱动不可用时，退化为"手动音频设备选择"模式
   - 提示用户将语音软件（微信/Discord等）的音频输出切换到耳机
   - 将游戏/共享应用的音频输出留在扬声器
   - 应用仅捕获扬声器的 WASAPI 环回音频
3. **效果差异**：降级模式下需要用户手动操作音频路由，但回声消除仍可通过 AEC 实现
4. **UI 提示**：在音频控制面板显示当前模式标识（"驱动模式" / "手动模式"）

### 5.5 音频编解码参数

| 参数 | 值 |
|------|-----|
| 编码器 | Opus (RFC 6716) |
| 采样率 | 48kHz |
| 声道 | 立体声（应用音频）/ 单声道（语音） |
| 比特率 | 128kbps（应用音频）/ 64kbps（语音） |
| 帧长 | 10ms（语音）/ 20ms（应用音频） |

## 6. 房间管理与协议

### 6.1 房间生命周期

```
创建房间 ──▶ 等待成员 ──▶ 活跃中 ──▶ 结束
    │              │          │
    ▼              ▼          ▼
  生成房间ID    成员加入/离开  开始/停止共享
  分配端口      心跳检测      流控制
```

### 6.2 应用层协议

基于 Protobuf over TCP/tsnet：

| 消息类型 | 方向 | 用途 |
|----------|------|------|
| `RoomCreate` | 请求 | 创建房间，返回房间ID和密钥 |
| `RoomJoin` | 请求 | 携带房间密钥加入 |
| `AuthKeyDistribute` | P2P | 房间创建者向新成员发送 Tailscale auth key，用于加入团队虚拟网络 |
| `PeerAnnounce` | 广播 | 新节点上线通知 |
| `StreamStart` | 请求 | 开始屏幕/音频共享 |
| `StreamStop` | 请求 | 停止共享 |
| `StreamOffer` | P2P | SDP offer（WebRTC语音通道） |
| `StreamAnswer` | P2P | SDP answer |
| `VoiceState` | 广播 | 语音状态变更（静音/开麦/正在说话），更新成员列表图标 |
| `Heartbeat` | 周期 | 连接保活（5秒间隔） |
| `ChatMessage` | 广播 | 文字聊天（可选） |

### 6.3 节点发现

通过 tsnet 的 MagicDNS 或直接查询 Tailscale 网络中的在线节点，匹配应用层的房间成员列表。

## 10. 关键技术难点与应对策略

| 难点 | 应对策略 |
|------|----------|
| 应用级音频分离 | 虚拟音频设备驱动方案，长期需实现内核级音频过滤 |
| Go 调用 Windows 底层 API | CGO 桥接 + 独立 C++ 动态库，使用 `syscall`/`go-ole` 操作 COM 接口 |
| P2P 打洞成功率 | tsnet 内置 STUN/TURN + 自建 DERP 中继保底 |
| 虚拟音频驱动开发 | 基于 AVStream/WMF 框架，参考 Windows Audio Session API |
