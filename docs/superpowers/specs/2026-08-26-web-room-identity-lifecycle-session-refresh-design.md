# 网页房间身份、生命周期、会话与列表刷新设计

## 目标

- 已登录用户创建房间时，房间 ID 固定使用用户 ID，不再使用随机房间名。
- 对用户取消房主概念。任意用户离开都不影响其他成员，房间只在最后一名成员离开时关闭。
- 同一设备登录后保持登录状态，除非用户主动退出或持久会话到期。
- 房间列表后台刷新时保持现有内容和布局稳定，不再呈现整块重新加载的跳动。

## 兼容策略

保留现有 WebSocket JSON 中的 `closeOnOwnerLeave` 和 `owner` 字段用于兼容旧客户端，但服务器忽略关闭请求，并始终向客户端报告 `owner: false`。网页不再发送或展示房主相关配置和标签。控制平面内部用于首个成员建立房间记录的角色字段不作为用户权限或房间生命周期依据。

## 前端行为

- “创建我的房间”使用 `config.user` 作为房间 ID；仅在未登录兼容模式下回退到服务器随机房间名。
- 移除“离开后关闭自己创建的房间”复选框和 URL 参数解析。
- 首次房间列表请求显示加载状态；定时轮询和手动刷新保留旧列表，只让刷新按钮显示进度。
- 请求失败时保留最后一次成功列表，并提供非跳动的错误与重试状态。
- 成员列表只显示“你”和“共享中”等实际状态，不显示“房主”。

## 服务端行为

- 创建房间时不记录会导致关闭房间的所有者状态。
- 任一用户断开后，如果还有成员则继续通知成员列表；只有成员数为零时才回收房间。
- 登录 Cookie 使用 30 天持久有效期。主动退出使用过期 Cookie 明确删除设备会话。

## 验证

- 源码测试验证用户 ID、无房主 UI、静默刷新状态分离和持久会话配置。
- Go 行为测试验证创建者先退出时房间及剩余成员仍存在，最后一名成员退出后房间关闭。
- Cookie 测试验证登录响应包含持久有效期，退出响应删除 Cookie。
- 完整前端构建、补丁链重放、运行时集成测试和桌面/移动浏览器检查均需通过后再部署。
