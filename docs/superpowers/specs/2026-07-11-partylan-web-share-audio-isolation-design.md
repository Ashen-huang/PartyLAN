# PartyLAN 网页共享音频来源隔离设计

## 背景

网页端当前提供“窗口/标签页音频”和“整个系统音频”选项，并向
`getDisplayMedia()` 传递 `systemAudio`、`windowAudio` 等偏好。屏幕共享规范允许
浏览器忽略这些偏好，因此仅依赖采集前约束不能保证普通窗口共享不会携带整个系统
的声音。

本设计只修复服务器网页端共享。PartyLAN 原生客户端的进程 loopback 路径不在本轮
范围内，也不修改 Screego 基础 bundle、网页主题或页面布局。

## 目标

- 标签页共享可以携带该标签页音频。
- 选择整个屏幕时可以显式开启系统音频。
- 普通应用窗口、来源未知或浏览器忽略偏好时绝不发送系统音频。
- 音频被安全策略移除时继续共享画面，并向用户给出明确提示。
- Presence、共享租约和诊断数据反映实际生效的音频模式。

## 非目标

- 不通过网页 API 实现 Windows 进程级音频捕获。
- 不根据浏览器版本、用户代理或本地化音轨名称推测音频来源。
- 不要求浏览器选择器隐藏所有不适用的共享来源；最终保护在采集结果返回后执行。

## 音频模式

网页设置保留三个互斥模式：

| 模式 | 采集前偏好 | 允许保留音频的画面来源 |
| --- | --- | --- |
| 标签页音频 | `systemAudio: exclude`、`windowAudio: exclude` | `browser` |
| 全屏系统音频 | `systemAudio: include`、`windowAudio: exclude` | `monitor` |
| 不共享音频 | `audio: false` | 无 |

“全屏系统音频”只表示用户希望在选择整个屏幕时启用系统音频。若用户在该模式下改选
标签页或普通窗口，采集后的音频仍会被移除。

## 采集后安全校验

`getDisplayMedia()` 返回后、流进入 P2P/SFU 发布路径前，读取视频轨
`getSettings().displaySurface`，并统一执行音频清理：

1. 标签页音频模式只接受 `browser`。
2. 全屏系统音频模式只接受 `monitor`。
3. 不共享音频、`window`、空值和未知值均不接受任何音频。
4. 不接受时，对每条音频轨调用 `stop()`，再从 `MediaStream` 中移除。
5. 清理失败不得阻止视频共享，但不得把仍存活的音频轨加入任何 PeerConnection。

不能使用音轨 `label` 作为安全依据；该字段由浏览器实现决定，可能本地化或变化。

## 状态与提示

采集激活时保存本次共享的实际音频模式：

- `tab`：标签页音频轨已保留。
- `system`：全屏系统音频轨已保留。
- `off`：没有可发布音频，或音频已由安全策略移除。

共享 claim 发生在浏览器选择器之前，可以暂时携带用户请求模式；采集返回后，首次
room-state 更新及后续 heartbeat 必须使用实际模式。共享停止后重置为 `off`。

当用户请求音频但因来源不匹配被移除时，显示一次非阻塞提示：

`为防止泄露系统声音，窗口共享已自动关闭音频。`

提示复用现有网页通知层或同等的注入提示能力，不修改主题 CSS、基础布局和 Screego
bundle。单次共享只提示一次。

## 代码边界

主要修改：

- `server/screego/deploy/inject.js`
- 对应的网页注入 Node 测试
- 必要时扩展服务端 stats 字段白名单，但不得记录音轨名称或其他敏感媒体信息

新增的来源判定与流清理逻辑应保持为可独立测试的纯函数或小型辅助函数，采集预热
路径与普通 `getDisplayMedia` 路径必须复用同一个校验入口。

## 测试

自动测试至少覆盖：

1. 标签页模式生成排除系统/窗口音频的采集偏好。
2. 全屏系统模式生成包含系统音频、排除窗口音频的采集偏好。
3. 标签页模式加 `browser` 来源保留音频。
4. 标签页模式加 `window`、`monitor` 或未知来源移除音频。
5. 全屏系统模式加 `monitor` 来源保留音频。
6. 全屏系统模式加 `window`、`browser` 或未知来源移除音频。
7. 被移除的音频轨会停止且不会被 P2P/SFU 发布。
8. 预热采集和普通采集执行相同校验。
9. 实际模式为 `off` 时 Presence/租约 heartbeat 不再上报请求模式。
10. 现有跨端兼容、自适应码率和首次房间连接测试不回归。

## 部署与回滚

部署前备份生产 `inject.js`、nginx 配置和注册控制服务文件，并确认无活动房间。上线
后用真实 Chromium 分别选择标签页、普通窗口和整个屏幕，检查发送端音频轨及观众端
听感。

若出现标签页音频被错误移除、显式全屏系统音频不可用、视频共享失败或网页基础流程
回归，立即恢复上一版 `inject.js` 并重载 Nginx。

## 验收标准

- 普通窗口共享不能让观众听到其他应用、通知或语音软件声音。
- 标签页共享仍能发送标签页音频。
- 选择整个屏幕并启用全屏系统音频时，观众能听到系统音频。
- 来源未知时默认静音，而不是猜测或回退到系统音频。
- 音频安全清理不造成黑屏、共享退出或共享租约泄漏。
