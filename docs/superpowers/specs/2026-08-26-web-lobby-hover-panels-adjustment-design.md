# PartyLAN 网页大厅紧凑布局与房间侧栏悬停修正

**日期：** 2026-08-26  
**状态：** 已确认  
**范围：** 仅网页端 Screego 原生 React UI，不修改桌面客户端、媒体协议或移动端底部收纳流程

## 问题

- 房间外大厅卡片最大宽度和分区留白过大，在桌面视口中显得横向过长、整体比例松散。
- 房间内桌面媒体查询把左右面板内容强制设为可见，覆盖了原定的侧边悬停显示行为。
- 桌面端不应重新出现收纳按钮；移动端仍需保留底部按钮和点击展开抽屉。

## 设计

### 房间外大厅

- 大厅主卡片最大宽度由 900px 收紧至 720px，窄屏仍使用可用宽度的 100%。
- 头部、房间列表区和“更多”区统一使用更紧凑的 16px/20px 间距节奏。
- 主创建按钮保持完整宽度和明确主操作层级，但高度收紧至 48px。
- 房间列表保留稳定的最小高度，单行房间高度收紧至 56px，避免刷新时发生布局跳动。
- 登录区、房间数据、“更多”内容和现有功能保持不变。

### 房间内桌面侧栏

- 左右侧各保留 24px 透明边缘热区，不显示收纳图标。
- 面板默认使用 `transform` 移出对应视口并设为透明，不占据视频布局空间。
- 鼠标悬停对应边缘、键盘焦点进入面板或面板被显式激活时，完整内容在 160-200ms 内滑入。
- 热区与展开面板共同维持悬停状态，指针移入面板后不会立即收起。
- 隐藏内容不接收指针事件；显示后恢复交互，避免不可见面板阻挡视频操作。
- `prefers-reduced-motion` 下取消过渡，但保留显隐状态。

### 移动端

- 700px 及以下、无 hover 或粗指针设备继续使用底部成员/共享入口。
- 点击入口展开底部抽屉，关闭按钮和 Escape 行为保持不变。
- 桌面透明热区不在移动端启用。

## 验证

- 源码测试覆盖 720px 大厅宽度、紧凑尺寸、桌面默认隐藏、hover/focus 显示和 24px 热区。
- 生产构建通过后，在桌面视口验证左右面板隐藏、对应边缘悬停展开、离开收起和视频区域不被阻挡。
- 在手机视口验证底部收纳入口与抽屉仍可用，且大厅无横向滚动。
- 在干净源码树重放完整补丁链，并运行现有网页与运行时回归测试。

## 回滚

撤销本次新增网页补丁并恢复上一版不可变镜像即可；不涉及用户数据或服务端协议迁移。
